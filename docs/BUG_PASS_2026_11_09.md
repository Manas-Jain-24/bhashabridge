# Multilingual bug pass — 9 November 2026

This pass reproduced 12 failing edge-case tests before changing the code. It then added further coverage for Bengali Unicode output, concurrent model requests, tutor outages, and explanation validation.

Fixed:

- Whitespace-only analyze/translate/transliterate requests returned success or reached the model. All text endpoints now strip and reject empty input; explanation input is also bounded to 2,000 characters.
- Bengali text could be processed under a Hindi source tag. Native-script mismatches now return a useful HTTP 422 response; script checks distinguish letters/marks from shared punctuation and digits.
- Analyze silently switched an explicitly selected target when source and target resolved to the same language. Explicit conflicting targets now return HTTP 422. Legacy default-target inference remains available when no target is supplied.
- Mixed native/Roman input skipped conversion. Analyze, model input, and reviewed-memory lookup now convert Roman tokens while preserving native text.
- The neural adapter returned shared cached dictionaries and stale source text on a case-insensitive hit. Cached responses are copied and use the current request's source text. Cache operations are locked.
- Concurrent neural requests could share processor entity state. Preprocessing, generation, and postprocessing now run under one inference lock. A concurrent regression checks isolation.
- Devanagari proper-name placeholders were unsuitable for cross-script Bengali output. The legacy name shielding is limited to the Hindi–Marathi pair; Bengali relies on the neural model's entity handling.
- Bengali phonetic mapping could emit unassigned characters for Hindi 'व'. Script exceptions now map to assigned Bengali letters, with readable Roman fallback for unsupported mappings.
- Malformed Gemini JSON could break response validation. Strict typed validation now rejects malformed explanations and falls back safely. A configurable model and 15-second default timeout replace four sequential model attempts; SDK retries are disabled.
- Language changes retained stale errors/drawer state, and swapping languages retained the original input after a translation. Invalidating a result now closes its drawer and clears stale errors; swap uses translated native text when available.
- Explanation mini-quizzes could show duplicate choices or apply Marathi distractors to Hindi answers. Quizzes require Marathi target examples and three distinct choices; quiz selection resets on a new result.
- Clipboard failures were reported as success, and speech could continue after a result changed. Copy now handles rejection and speech is stopped on result change/unmount.

Verification: 125 backend tests passed, including all existing regressions; TypeScript and Vite production build passed. Tests use isolated databases and check that production databases stay unchanged. Browser checks covered a wrong-script error, recovery after changing source language, mixed Bengali/Roman preview and translation, and swapping a translated result. Bengali translation/romanization remains beta; this pass does not establish linguistic accuracy or microphone/device voice support.

Changes are local. Existing staged presentation PDFs and run_demo.bat were left as they were; no commit or push was made by this pass.
