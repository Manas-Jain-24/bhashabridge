# Production audit

Baseline `b36273b13b173f754e11baf83afa050824941fe7`. The findings below describe the starting source. See `PRODUCTION_READINESS.md` for current verification.

| Severity | Baseline evidence | Impact | Resolution |
| --- | --- | --- | --- |
| P1 | `backend/app/core/config.py:75–82`, `backend/app/core/auth.py:45–71`, `docker-compose.yml:4–25` | Production could start on SQLite or with test flags. Mutations accepted missing origins, and development services published database ports on all interfaces. | Require PostgreSQL, secure cookies and a configured HTTPS origin. Use trusted hosts and private production services. |
| P1 | `backend/app/api/routes/auth.py:19–82`, `backend/app/main.py:42–57` | IP-only authentication limits did not protect a targeted account. Signup could disclose username availability or leave a partially registered account. Default validation errors could echo submitted values. | Require production invitations, bound password work, issue sessions atomically and sanitize errors. |
| P1 | `backend/app/models/migrations.py:7–19`, `backend/scripts/init_db.py:21–34`, `backend/app/models/seed.py:80–110` | `create_all` did not migrate existing columns. Manual setup bypassed schema versioning, and an explicit seed ID could collide with the first PostgreSQL-generated user ID. | Use explicit schema revisions, a single migration entry point, and production catalog-only seeding. Test existing schemas and sequence behavior. |
| P1 | `backend/app/services/vocabulary/srs_service.py:79–126`, `backend/app/services/gamification/arcade.py:129–193`, `backend/app/api/routes/auth.py:122–141` | Concurrent first reviews and multiple games could race. A request already authorized at deletion time could write new learner data. | Serialize authenticated account writes, preserve unique reward keys, and test races on PostgreSQL. |
| P1 | `backend/app/api/routes/explain.py:18–29`, `backend/app/services/translation/indictrans2.py:103–136`, `ml/transliteration/predictor.py:37–61` | Standalone explanations could transmit learner text in global local mode. IndicTrans2 could load unpinned remote code and the legacy transliterator allowed pickle loading. | Enforce the effective mode at the provider boundary and provision verified offline snapshots and weights. |
| P2 | `backend/app/services/explanation/llm_tutor.py:143–189`, `backend/app/services/translation/neural_transformer.py:38–65`, `frontend/src/services/http.ts:1–21` | Provider deadlines and outage handling differed. One model cache was unbounded and clients had no network deadline. | Apply common provider limits and bounded retention, and centralize browser request cancellation and errors. |
| P2 | `scripts/check_corpus_leakage.py:11–26`, `scripts/review_workflow.py:66–90`, `data/quality/evaluation-draft-v1/manifest.json:2–13` | Leakage checks varied by corpus. Publication could race with a revision, and draft references could not establish human adequacy. | Bind publication to a reviewed version and audit runtime and export datasets. Keep draft diagnostics separate from reference scores. |
| P2 | `frontend/playwright.config.ts:4–13`, `.github/workflows/ci.yml:5–46`, `scripts/database_ops.py:1–41` | CI exercised a disposable SQLite and Vite stack. It provided no production HTTPS, PostgreSQL recovery or dependency scanning evidence. | Test the production stack, versioned upgrades, recovery and supply chain in CI. |
| P2 | `frontend/index.html:9–11`, `frontend/src/utils/speechEngine.ts:99–147`, `data/README.md:14–18` | Third-party fonts cause external requests. Browser speech may use a remote service. Legacy records of unknown provenance need review before redistribution. | Self-host production fonts where available, disclose browser speech behavior, preserve attributions and document distribution limits. |

Static inspection identified no P0. Existing defenses include scrypt password hashing, hashed revocable sessions, reviewer role checks, versioned correction decisions, unique reward keys, cloud quota counters and a bounded inference pool. These are starting controls. Runtime, concurrency and model claims require the checks in the readiness checklist.
