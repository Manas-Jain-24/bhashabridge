# Bug audit — 12 November 2026

This pass tests application behavior, not a certified translation-accuracy score.
It combines regression tests, the production build, dataset checks, real browser
requests, controlled browser failure scenarios, and one live Gemini request.

## Confirmed defects and fixes

| Defect | Reproduction | General fix |
| --- | --- | --- |
| English gloss could contradict protected values | Native/Roman said 7 books; English saying 8 books, dropping 7, or adding a handle was accepted | Apply identifier/numeral preservation to the English field too; reject the candidate and retain the labeled local fallback |
| Numeric guard lost information | `-7` equaled `7`; `.5` equaled `5`; a Bengali digit inside a URL/handle could be rewritten | Preserve signs and leading decimals; normalize equivalent Indic digits only outside opaque identifiers |
| Auto-detected Bengali was normalized as Hindi | `আমি jana চাই` became `আমি jaana চাই` before language detection | Detect the language before applying language-specific chat normalization |
| Sentence explanations matched unrelated text | A short substring or a learning keyword returned an entire stored explanation, including words absent from the input | Require the complete source **and** target pair for stored sentence explanations; otherwise use the general path |
| Reverse explanations had forward-direction fields | Marathi→Hindi greeting returned Hindi→Marathi vocabulary/examples | Orient vocabulary, grammar-pattern fields, and examples to the requested direction without mutating stored entries |
| “Roman Script” contained English or native text | `नमस्कार` showed `hello` in its Roman column; reverse/dynamic rows could contain Devanagari | Generate target-language Roman spelling independently of the meaning |
| Word splitting damaged Indic text | Python `\w` split vowel marks out of words such as `अनजाना` | Keep combining marks with their words; distinguish punctuation from letters/marks at term boundaries; require each lexicon term on its own language side |
| Mobile preview covered the input | At 390px, a longer spelling estimate hid the final input line | Put the wrapping estimate beneath the textarea in normal document flow |

Unmatched residual text is now labeled as unaligned, rather than automatically
being called a verified predicate or grammatical construction. These fixes do
not establish that every remaining rule, gloss, or alignment is linguistically correct.

### Live hybrid smoke check

One real `/api/analyze` request, using the configured local IndicTrans2 model and
Gemini assistance, returned HTTP 200 in **22.24 seconds**:

| Field | Observed result |
| --- | --- |
| Original | `Mujhe 7 kitabein chahiye.` |
| Interpreted source | `मुझे 7 किताबें चाहिए।` |
| Bengali | `আমার 7টি বই চাই।` |
| Roman Bengali | `Amar 7ti boi chai.` |
| English | `I want 7 books.` |
| Provenance | `gemini-contextual`, `context_status=assisted` |
| Local draft provider | `indictrans2-320m-neural` |

This confirms that the configured Gemini credential worked for this request and
that the numeral survived all returned views. The output is **model generated,
not bilingual-human-reviewed**. One timing is not a latency percentile or a GPU
comparison. This pass does not add Bengali-source hybrid quality evidence.

## Remaining limits

- Translation correctness, ambiguity handling, and rule explanations still need
  independent bilingual review. Structural validation cannot prove meaning.
- Numeric validation deliberately requires numeric notation to survive; a model
  that spells `7` as `seven` will be rejected. Opaque identifier spelling is exact.
- This was not a full neural/FLORES accuracy benchmark, load test, accessibility
  audit, or multi-user security assessment. Models/weights were not retrained.
- A Starlette/httpx test-client deprecation warning remains. It does not fail the
  suite; migrate the test dependency separately with compatibility checks.
- The browser checks currently use an isolated Playwright CLI session, not a
  browser suite in CI. The existing CI runs backend tests, data checks, and build.
- Several endpoints use `user_id=1`. The project is still a single-user local
  application; it needs identity and per-user isolation before a public service.
